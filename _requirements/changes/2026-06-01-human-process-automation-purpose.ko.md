# 인간 프로세스 자동화 목적 요구사항 변경

## 변경 개요

- 날짜: 2026-06-01
- 출처 요청: `UR-2026-06-01-034`
- 추가 요구사항: `REQ-WS-045`
- 작업 모드: `governance`

## 사용자 요청 요약

사용자는 이 플랫폼의 본질이 사람의 반복적인 작업을 계속 줄이고, 효율적인 방법을 만들어 내며, 시간을 줄이고, 인간과 최대한 유사한 프로세스를 찾아내 자동화하는 것이라고 정의했다.

## 변경 내용

`REQ-WS-045`를 추가해 반복 작업 감소와 인간 프로세스 모델링을 플랫폼의 최상위 목적 원칙으로 승격한다.

- 사람의 반복적인 조사, 판단, 실행, 검증 과정을 관찰한다.
- 그 과정을 재현 가능한 단계와 기준으로 모델링한다.
- 반복 가치가 있으면 가장 작은 durable asset으로 승격한다.
- 자동화는 인간 판단 지점, 검증, rollback 경계를 보존한다.

## 근거

- Google SRE의 toil 개념은 manual, repetitive, automatable work를 줄여 장기적인 engineering work에 시간을 쓰는 방향을 제시한다.
- Google SRE workbook은 문서화된 수작업을 컴포넌트로 쪼개 재사용 가능한 automation/library로 만드는 방식을 권한다.
- RPA/업무 자동화 자료는 반복적이고 rule-based인 작업을 자동화해 오류를 줄이고 사람이 더 전략적인 작업에 집중하도록 하는 방향을 설명한다.
- IBM LiveAction 연구는 사용자가 자신이 반복 작업을 하고 있음을 잘 인식하지 못하지만, 실제 웹 사용 데이터에는 자동화 가능한 반복 행동이 존재한다고 설명한다.

## 영향

- 철학 문서와 플랫폼 정체성 문서가 “반복 감소와 시간 절감”을 더 명시적으로 말한다.
- capability governance는 자동화 후보를 판단할 때 시간 절감, 반복 빈도, 인간 프로세스 재현성, 검증/rollback 경계를 같이 본다.
- 향후 도구/스킬/에이전트 제안은 단순히 만들 수 있는지가 아니라 실제 반복 작업을 줄이는지 평가해야 한다.
