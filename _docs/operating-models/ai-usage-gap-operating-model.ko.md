# AI 사용 격차 운영 모델

## 목적

AI를 잘 쓰는 사람과 잘 못 쓰는 사람의 차이를 개인의 재능 차이가 아니라 반복 가능한 작업 구조의 차이로 다룬다. 이 플랫폼은 사용자가 더 좋은 프롬프트를 쓰게 만드는 데서 끝나지 않고, 좋은 AI 사용 방식을 요구사항, 스펙, 조사, 검증, 도구, 스킬, 히스토리로 바꿔 축적한다.

## 핵심 관찰

AI를 잘 못 쓰는 사람에게 자주 보이는 문제는 다음이다.

- 목표와 성공 기준을 명확히 주지 않는다.
- AI가 잘하는 작업과 위험한 작업의 경계를 구분하지 않는다.
- 첫 답변을 그대로 믿거나 바로 포기한다.
- 근거, 테스트, 출처, 반례 확인 없이 결과를 사용한다.
- 좋은 프롬프트와 작업 흐름을 저장하지 않아 매번 다시 시작한다.
- 반복 가능한 작업을 도구나 템플릿으로 만들지 않는다.
- AI 사용을 숨기거나 공유하지 않아 조직/프로젝트 차원의 학습이 일어나지 않는다.

AI를 잘 쓰는 사람은 다음이 다르다.

- 산출물의 목적, 독자, 제약, 입력 자료, 성공 기준을 먼저 정의한다.
- AI를 정답 기계가 아니라 탐색자, 초안 작성자, 비평가, 변환기, 검증 보조자로 사용한다.
- 작업을 계획, 근거 수집, 구현, 검증, 평가로 나누고 반복한다.
- 웹 검색, 공식 문서, 테스트, 로컬 파일, evaluator, 인간 판단을 함께 사용한다.
- AI가 잘하는 영역과 불안정한 영역이 고르지 않다는 점을 전제로 한다.
- 반복되는 좋은 사용법을 프롬프트, 워크플로, 템플릿, 도구, 스킬로 승격한다.

## 간극을 줄이는 방식

1. 요청을 더 좋게 만든다: 목표, 맥락, 제약, 예시, 성공 기준을 붙인다.
2. 작업 적합성을 본다: AI가 초안 작성에 적합한지, 검색이 필요한지, 코드/테스트가 필요한지, 인간 판단이 필요한지 분류한다.
3. 한 번에 끝내지 않는다: 초안, 비평, 수정, 검증 루프를 짧게 돈다.
4. 근거를 붙인다: 사실 주장에는 출처, 코드에는 테스트, 숫자에는 단위/base/기간/방법론을 붙인다.
5. 반복 패턴을 저장한다: 다음에도 쓸만하면 prompt, workflow, template, tool, skill, config 중 가장 작은 자산으로 승격한다.

## 플랫폼 반영

- 설정: `agent-platform/configs/usage/ai-usage-gap-profile.json`
- 워크플로: `_ops/workflows/59-bridge-ai-usage-gap.md`
- 프롬프트: `_ops/prompts/89-bridge-ai-usage-gap.md`
- 메모리: `agent-platform/configs/memory/bootstrap-manifest.json`의 warm anchor

## 운영 원칙

- 사용자를 비난하지 않는다. gap은 문해력, 맥락, 검증, 작업 구조, 도구화, 학습 루프의 문제로 다룬다.
- 모호한 요청은 곧바로 거절하지 않는다. 위험이 낮으면 합리적 가정을 세우고 진행하되, 가정과 검증 경로를 남긴다.
- 위험이 높거나 사용자 선호가 결정적인 경우에는 `clarification_needed`로 되돌린다.
- 좋은 AI 사용법은 대화에 머물지 않고 저장소 자산으로 남긴다.
