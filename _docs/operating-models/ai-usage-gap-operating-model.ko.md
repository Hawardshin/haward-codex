# AI 사용 격차 운영 모델

## 목적

AI를 잘 쓰는 사람과 잘 못 쓰는 사람의 차이를 개인의 재능 차이가 아니라 반복 가능한 작업 구조의 차이로 다룬다. 이 플랫폼은 사용자가 더 좋은 프롬프트를 쓰게 만드는 데서 끝나지 않고, 좋은 AI 사용 방식을 요구사항, 스펙, 조사, 검증, 도구, 스킬, 히스토리로 바꿔 축적한다.

## 핵심 관찰

AI를 잘 못 쓰는 사람에게 자주 보이는 문제는 다음이다.

- 목표와 성공 기준을 명확히 주지 않는다.
- 질문과 지시가 모호하거나, 원하는 결론을 유도하거나, 편향되어 있다.
- AI가 잘하는 작업과 위험한 작업의 경계를 구분하지 않는다.
- 첫 답변을 그대로 믿거나 바로 포기한다.
- 근거, 테스트, 출처, 반례 확인 없이 결과를 사용한다.
- 좋은 프롬프트와 작업 흐름을 저장하지 않아 매번 다시 시작한다.
- 반복 가능한 작업을 도구나 템플릿으로 만들지 않는다.
- AI 사용을 숨기거나 공유하지 않아 조직/프로젝트 차원의 학습이 일어나지 않는다.

AI를 잘 쓰는 사람은 다음이 다르다.

- 산출물의 목적, 독자, 제약, 입력 자료, 성공 기준을 먼저 정의한다.
- 질문을 중립적으로 만들고, 반대 근거와 대안까지 요구한다.
- 출력 형식, 깊이, 검증 기준, 예시를 명확히 둔다.
- AI를 정답 기계가 아니라 탐색자, 초안 작성자, 비평가, 변환기, 검증 보조자로 사용한다.
- 작업을 계획, 근거 수집, 구현, 검증, 평가로 나누고 반복한다.
- 웹 검색, 공식 문서, 테스트, 로컬 파일, evaluator, 인간 판단을 함께 사용한다.
- AI가 잘하는 영역과 불안정한 영역이 고르지 않다는 점을 전제로 한다.
- 반복되는 좋은 사용법을 프롬프트, 워크플로, 템플릿, 도구, 스킬로 승격한다.

## 간극을 줄이는 방식

1. 요청을 더 좋게 만든다: 목표, 맥락, 제약, 예시, 성공 기준을 붙인다.
2. 잘못된 지시를 고친다: 편향, 유도형 결론, 숨은 선호, 과도하게 큰 요청, 검증 없는 최신 주장 요청을 중립적 task brief로 바꾼다.
3. 작업 적합성을 본다: AI가 초안 작성에 적합한지, 검색이 필요한지, 코드/테스트가 필요한지, 인간 판단이 필요한지 분류한다.
4. 한 번에 끝내지 않는다: 초안, 비평, 수정, 검증 루프를 짧게 돈다.
5. 근거를 붙인다: 사실 주장에는 출처, 코드에는 테스트, 숫자에는 단위/base/기간/방법론을 붙인다.
6. 반복 패턴을 저장한다: 다음에도 쓸만하면 prompt, workflow, template, tool, skill, config 중 가장 작은 자산으로 승격한다.

## 질문/지시 품질 원칙

LLM은 prompt와 context에 조건화된 확률적 출력을 생성한다. 따라서 좋은 질문은 결과를 장식하는 문장이 아니라, 모델이 어떤 분포의 답을 생성할지 바꾸는 입력 설계다.

즉 "질문을 잘해야 한다"는 사용자의 표현은 단순한 prompt 요령이 아니라 운영 원칙이다. 잘못된 질문은 모델의 한계와 별개로 나쁜 조건을 제공하며, 특히 편향적 지시와 결론 유도형 지시는 그 방향으로 그럴듯한 답을 만들 위험을 키운다.

좋은 지시는 최소한 다음을 포함한다.

- 목표: 무엇을 바꾸거나 결정하려는가.
- 맥락: 어떤 자료, 제약, 과거 결정이 중요한가.
- 출력 계약: 형식, 깊이, 톤, 예시, 제외 범위, 성공 기준.
- 중립성: 원하는 결론을 증명하라고 하지 않고 대안과 반대 근거를 함께 요구하는가.
- 검증: 어떤 출처, 테스트, 계산, 리뷰로 확인할 것인가.
- 불확실성: 무엇을 가정, 미확인, 사용자 결정 필요로 표시할 것인가.

흔한 잘못된 지시:

- `잘 만들어줘`: 기준이 없다.
- `이게 최고라는 걸 증명해줘`: 결론을 유도한다.
- `반대하는 사람은 왜 틀렸는지 설명해줘`: 편향된 프레임이다.
- `최신 수치로 설명해줘`: 출처, 날짜, 정의, 지역이 없다.
- `조사하고 계획하고 코드까지 다 해줘`: 서로 다른 검증 단계를 한 요청에 섞는다.

이런 지시는 실행 전에 목표, 맥락, 제약, 출력 형식, 성공 기준, 검증 경로를 포함한 중립적 지시로 재작성한다.
재작성한 지시는 사용자의 실제 목적은 보존하되, 사실 주장과 선호를 분리하고, 대안/반대 근거/불확실성을 확인할 수 있어야 한다.

## 역질문과 질문 예산

모호한 지시는 무조건 추측해서 진행하지 않는다. 사용자의 목적, 맥락, 제약, 출력 계약, 성공 기준 중 결과를 크게 바꾸는 정보가 빠져 있으면 에이전트가 먼저 역질문한다.

다만 역질문은 작업을 앞으로 움직이기 위한 장치이지, 대화를 끝없이 늘리는 절차가 아니다. 기본 규칙은 다음이다.

- 질문은 보통 1회, 많아도 2회 이내로 제한한다.
- 한 번에 묻는 질문은 최대 3개로 제한하고, 가장 큰 결정 영향이 있는 것부터 묻는다.
- 로컬 파일, 기존 스펙, 검색, 테스트로 확인할 수 있는 것은 사용자에게 묻지 않는다.
- 위험이 낮고 되돌릴 수 있는 작업은 합리적 가정을 적고 진행한다.
- 답이 없거나 계속 모호하면 기본 가정, 추천 선택지, 선작업 후 확인, 명시적 보류 중 하나로 수렴한다.

좋은 역질문은 “어떻게 할까요?”가 아니라 “이 결정을 고르면 결과가 이렇게 달라진다”를 보여준다. 가능하면 2-3개 선택지와 추천 기본값을 함께 제공한다.

### 질문 대기와 비차단 진행

역질문이 필요한 상태가 곧 전체 작업 중단을 뜻하지 않는다. 답변 없이는 결정할 수 없는 부분만 `blocked_decision`으로 격리하고, 그 결정과 독립적인 조사, 출처 수집, 대안 비교, 초안 작성, 테스트, 검증, 문서화, 리스크 정리는 계속 진행한다.

비차단 진행의 기본 규칙은 다음이다.

- 질문은 `question_id`, 결정 영향, 기다리는 이유, 답변 후 수정 범위를 함께 남긴다.
- 전체 작업이 아니라 의존된 산출물이나 행동만 멈춘다.
- 계속 진행한 작업은 `unblocked_work`로 표시하고, 사용한 가정과 기본값을 명확히 적는다.
- 답변이 오면 가정과 답변을 비교해 영향을 받는 파일/결정만 병합하거나 수정한다.
- 되돌리기 어렵거나 위험한 작업은 진행하지 않고 명시적으로 보류한다.

이 규칙은 AI 시대의 큰 병목을 줄이기 위한 것이다. 사용자가 즉시 답하지 못해도 에이전트는 할 수 있는 일을 해두고, 사람의 결정이 필요한 지점만 작고 선명하게 남겨야 한다.

## 모델별 사용 전략

좋은 모델과 약한 모델은 같은 방식으로 다루면 안 된다. 특히 추론에 최적화되지 않은 약한 모델은 한 번의 답변이 불안정할 수 있으므로, 비용과 지연이 허용되고 작업 편차가 큰 경우 두 번의 독립 시도나 초안-비평-수정 loop를 기본 후보로 둔다.

다만 `두 번 물어보면 참이다`가 아니다. 두 결과가 같아도 그것은 agreement signal일 뿐이며, 사실 주장이나 중요한 판단은 출처, 테스트, 도구, evaluator, 인간 판단으로 검증해야 한다.

운영 규칙은 다음이다.

- 약한/비추론/불확실 모델: 작업을 작게 나누고, 2-pass 결과를 비교한 뒤 수렴점과 충돌점을 분리한다.
- 일반 모델: 예시, 출력 계약, 제약을 명확히 하고, 고분산 작업에서는 2-pass 또는 초안-비평-수정을 사용한다.
- 추론/강한 모델: 중복 호출을 먼저 늘리지 말고 목표, 맥락, 제약, 성공 기준, 검증 경로를 명확히 한다.
- 모든 모델: 반복 호출 결과를 근거로 착각하지 않고 별도 검증 경로를 둔다.

## 운영 원칙

- 사용자를 비난하지 않는다. gap은 문해력, 맥락, 검증, 작업 구조, 도구화, 학습 루프의 문제로 다룬다.
- 모호한 요청은 곧바로 거절하지 않는다. 위험이 낮으면 합리적 가정을 세우고 진행하되, 가정과 검증 경로를 남긴다.
- 모호한 요청이 결과를 크게 바꾸면 역질문하되, `clarification_budget`으로 질문 round와 질문 수를 제한한다.
- 역질문 답변을 기다릴 때도 전체 작업을 멈추지 않는다. 답변이 필요한 결정만 `blocked_decision`으로 격리하고, 영향 없는 작업은 `unblocked_work`로 계속 진행한다.
- 편향적이거나 결론을 유도하는 지시는 사용자의 의도와 사실 주장을 분리한 뒤 중립적으로 바꾼다.
- 위험이 높거나 사용자 선호가 결정적인 경우에는 `clarification_needed`로 되돌린다.
- 좋은 AI 사용법은 대화에 머물지 않고 저장소 자산으로 남긴다.
