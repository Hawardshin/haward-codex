# Presentation Reference Curator

Use this skill for presentation-agent work that needs design references, PPT/HTML slide examples, reusable assets, or evidence for presentation flow.

## Workflow

1. Run web-first intake before local planning. Search in separate lanes: HTML slide frameworks, PPT/template galleries, visual design galleries, asset libraries, presentation theory, and presentation AI research.
2. Store source metadata before storing files. Record URL, access date, source type, format, license status, download eligibility, HTML conversion path, design tags, quality signals, and notes.
3. Apply the license gate. Keep copyrighted, paid, account-gated, or unknown-license decks as metadata-only references. Download or convert raw PPT/PPTX/assets only when terms permit local reuse.
4. Prefer HTML-native references when the final deck should be HTML. For PPT/PPTX, choose one of: text-structure extraction, manual HTML rebuild, or separately researched high-fidelity conversion.
5. Separate evidence roles. Use official docs and license pages for factual claims, design galleries for visual inspiration, community metrics for discovery signals, and papers/guides for evaluation criteria.
6. Summarize reusable patterns into the owning project's `docs/research/` and keep catalog entries under `data/reference-index/`.
7. Before close-out, validate the catalog, run or document the conversion check, run a realistic forward-test scenario, evaluate the result against the user request, and record improvement ideas.

## Output Contract

- Project source catalog with provenance and conservative license status.
- Korean and English docs for durable research or requirements.
- Conversion notes for every PPT/PPTX-to-HTML attempt.
- Clear statement of which raw assets were not stored because license or terms were not verified.
