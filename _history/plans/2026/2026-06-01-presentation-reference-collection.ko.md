# 계획 기록: 발표 레퍼런스 수집 기반

## 작업 모드

- 선택 모드: `standard`
- 이유: 새 프로젝트 생성, 프로젝트 경계 등록, 스킬 생성, 데이터 구조, 테스트, 히스토리, 평가가 필요한 의미 있는 작업이다.

## 근거

- 웹 검색으로 HTML 발표 프레임워크, PPT 템플릿 갤러리, 디자인 갤러리, 에셋 라이브러리, 발표 이론, 변환 도구 후보를 확인했다.
- 기존 저장소 규칙상 새 관심사는 최상단 프로젝트 폴더로 분리해야 하므로 `presentation-agent/`를 만들었다.
- 저작권 위험 때문에 원본 PPT/에셋 대량 저장보다 출처 메타데이터와 라이선스 게이트를 우선했다.

## 실행 계획

1. 프로젝트 폴더와 README를 만든다.
2. 레퍼런스 카탈로그와 수집 정책을 만든다.
3. Python 검증 도구와 PPTX 텍스트-HTML 변환 도구를 만든다.
4. 요구사항과 스펙을 프로젝트 내부에 남긴다.
5. 발표 레퍼런스 큐레이터 스킬을 만든다.
6. 운영 레지스트리, 히스토리, 요청 추적, 작업 요약을 갱신한다.
7. 테스트와 스킬 검증을 실행한다.
8. 평가 파일을 만들고 커밋/푸시한다.

## 병렬화 판단

- 출처 수집은 향후 여러 lane으로 병렬화할 수 있다.
- 이번 작업은 같은 카탈로그와 레지스트리를 동시에 수정하므로 단일 agent가 직렬로 작성하고, 이후 병렬 수집은 merge gate를 두는 편이 안전하다.
