# 2026-05-31 계획 기록: 요구사항 관리

## 초기 지시 요약

사용자는 작업을 통해 요구사항을 정의하고, 그 요구사항을 계속 수정/검토하면서 이를 기반으로 만들어야 한다고 지시했다.

## 조사

- 웹 검색을 먼저 수행했다.
- 요구사항 관리, traceability matrix, 변경 관리, 변경 로그 관행을 확인했다.
- 요구사항은 요청 요약과 요청-결과 추적 사이에 별도 기준선 계층으로 두는 것이 적합하다고 판단했다.

## 계획

1. `_requirements/`를 공통 요구사항 계층으로 추가한다.
2. 공통 요구사항 기준선, 변경 기록, 검토 기록을 한영으로 만든다.
3. 요구사항 관리 정책, 템플릿, 프롬프트, 워크플로를 추가한다.
4. `requirements-manager-agent`를 추가한다.
5. `work-evaluator-agent`가 `requirements_targets` 누락을 blocking gap으로 보게 한다.
6. README, AGENTS, persistent instructions, memory bootstrap, 운영 인덱스, 시작/종료 워크플로, 히스토리, 리서치, 조율 보드를 연결한다.

## 공개 판단

요청 요약은 사용자의 의도를 보존하고, 요청-결과 추적은 결과를 연결한다. 하지만 실제 구현 기준이 될 요구사항 ID와 검증 방법이 없으면 반복 작업에서 기준이 흔들릴 수 있다. 따라서 요구사항 기준선을 별도 계층으로 두고, 변경과 검토 기록을 함께 남긴다.

## 완료 기준

- `_requirements/` 기준선, 변경, 검토 파일이 존재한다.
- 요구사항 관리 프롬프트/워크플로/에이전트가 존재한다.
- 평가 입력이 `requirements_targets`를 요구한다.
- 테스트, config checks, grounding, evaluation이 통과한다.
- 커밋 후 push한다.
