# 웹 검색 기록: 큰 범위 작업 미루지 않기

## 검색 시각

2026-06-06

## 쿼리

- `large scope software engineering don't defer break down and deliver incrementally project management best practices`
- `large scope decomposition software engineering deliver incremental slices avoid postponing broad scope`

## 확인한 내용

- Incremental delivery guidance는 큰 범위를 작고 완결된 increment로 나누는 쪽을 권한다.
- Scope control guidance는 deliverables, exclusions, acceptance criteria, change boundary를 명시해야 scope가 넓어져도 실행과 검증이 가능하다고 본다.
- Large project breakdown guidance는 큰 작업을 shippable increments와 validation points로 나누는 것이 uncertainty를 줄이고 early feedback을 만든다고 설명한다.

## 계획 영향

사용자 지시를 durable rule로 반영했다. 큰 범위는 미루거나 되돌려 넘기는 이유가 아니라 `first_executable_slice`, validation gate, continuation path로 바꿔 실행해야 한다.

## 한계

이번 검색은 특정 코드 구현을 위한 기술 선택이 아니라 운영 규칙 보강 근거로만 사용했다.
