# 사용자 요청 요약: 근본부터 재검토

## 원 요청

사용자는 이전 속도 최적화 이후에도 “너의 근본적인 부분부터 다시 살펴봐”라고 요청했다.

## 해석

- 국소 탭 prewarm이나 버튼 조정만 반복하지 말고, 데스크톱 앱의 renderer/runtime 구조 자체를 재검토한다.
- 성능 병목이 React tree, JS bundle 평가, 데이터 payload, native runtime 중 어디에 남아 있는지 냉정하게 본다.
- 바로 검증 가능한 구조 개선을 구현하고, 빌드/패키징까지 자동으로 실행한다.

## 이번 수용 기준

- 남은 root bottleneck을 근거와 함께 밝힌다.
- 위험이 낮은 첫 root boundary 개선을 구현한다.
- 성능 수치를 과장하지 않고 tradeoff를 기록한다.
- 내부 앱/DMG 패키징까지 완료한다.
