설치형 에이전트 플랫폼의 UX spine

Design intent 상태를 이해하고, 다음 행동을 선택하고, 근거를 확인하고, 막힘을 복구한다.

첫 실행은 설정 완료가 아니라 신뢰 형성이 목표다.

Command Center

사용자는 앱을 열자마자 “지금 무엇이 진행 중이고, 무엇이 막혔고, 내가 무엇을 결정해야 하는지” 알아야 한다.

대시보드는 프로젝트와 문서 숫자를 먼저 자랑하지 않는다. 현재 상태, next action, decision inbox, evidence trail, view mode를 먼저 보여주고 세부 문서는 drill-down으로 둔다.

Open workspace Review decisions Check evidence
Primary status Now / Needs attention

작업 상태와 주의 항목을 상단에서 고정적으로 보여준다.

Control User / Developer / Superadmin

보기 모드는 설치 모드와 분리된 렌즈다.

첫 실행 흐름

01

워크스페이스 선택

기존 repo 열기, 새 workspace 만들기, demo 둘러보기를 선택한다.

02

안전 경계 확인

읽을 위치, 제외 위치, `_private/` default deny, public snapshot 주의사항을 확인한다.

03

보기 렌즈 선택

사용자는 user view, 개선자는 developer, 소유자는 superadmin developer를 선택한다.

04

준비 검사

필수 오류만 막고, 선택 CLI와 알림 설정은 capability card로 보류한다.

05

운영 화면 진입

status, next action, evidence, decision inbox, history를 한 화면에서 본다.

운영 spine

Now 현재 상태

진행 중 작업, 활성 에이전트, 느린 단계, 최신 snapshot 시간을 보여준다.

Attention 막힘과 결정

사용자 답변이 필요한 항목만 decision inbox에 모으고 독립 작업은 계속한다.

Evidence 근거 trail

웹 검색, 요구사항, 스펙, 평가, 커밋을 사용자가 따라갈 수 있게 묶는다.

Recover 되돌림과 복구

실패한 검사, 누락된 CLI, 오래된 snapshot은 전체 앱 실패가 아니라 복구 가능한 상태다.

명확한 상태

사용자는 “무슨 일이 일어나는지”를 추측하지 않아야 한다.

사용자 통제

자동화는 진행하되 중요한 선택은 사람이 회수할 수 있어야 한다.
