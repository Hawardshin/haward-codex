# 설치형 앱 사용자 플로우

## 목적

이 문서는 `platform-desktop-app`이 단순한 기술 패키징 프로젝트가 아니라 사용자가 쉽게 설치하고 바로 쓸 수 있는 제품이 되기 위한 사용자 흐름을 정의한다.

핵심 기준은 다음이다.

- 설치 후 첫 화면에서 사용자가 무엇을 해야 하는지 즉시 보여준다.
- 선택해야 할 것이 많아도 필수와 선택을 분리한다.
- 선택하지 않은 선택지 때문에 전체 작업이 멈추지 않게 한다.
- 사용자 모드와 개발자/슈퍼어드민 모드를 분리한다.
- 모든 작업은 진행 상태, 병목, 산출물, 근거, 평가를 볼 수 있어야 한다.

상세 설정 원천은 `platform-desktop-app/configs/user-flow-registry.json`이다.

## 사용자 유형

| 유형 | 기본 화면 | 필요한 것 | 기본으로 숨길 것 |
| --- | --- | --- | --- |
| 작업 사용자 | `user` | 워크스페이스 열기, 프로젝트/히스토리 보기, 작업 시작, 질문 답변, 결과 검토 | raw config, 검증 내부 구조, 설치/배포 로그 |
| 플랫폼 빌더 | `developer` | 스펙/프롬프트/설정 편집, 검증 실행, 근거 추적, 로컬 변경 관리 | 실제 secret, 외부 계정 세션 |
| 슈퍼어드민 개발자 | `superadmin_developer` | 전체 프로젝트, 에이전트, 설정, 검증, 배포 게이트, 병목을 모두 확인 | 기본 숨김 없음 |

## 설치 후 첫 가치

첫 실행에서 가장 중요한 목표는 “모든 설정 완료”가 아니라 “워크스페이스를 열고 현재 상태를 보는 것”이다.

첫 화면의 우선순위는 다음 순서다.

1. 기존 워크스페이스 열기
2. 새 워크스페이스 만들기
3. 데모 워크스페이스로 둘러보기
4. 개발자 설정 열기

Slack, Discord, Teams, 외부 CLI, 고급 검증, 브라우저 자동화 같은 기능은 초기 사용을 막지 않는다. 누락된 기능은 설정 카드로 표시하고, 해당 기능만 비활성화한다.

## 첫 실행 흐름

```text
앱 실행
  -> 워크스페이스 열기 / 만들기 / 데모 선택
  -> 읽을 경로와 데이터 범위 확인
  -> 보기 모드 선택
  -> 필수 준비 상태 검사
  -> 선택 기능 상태 카드 생성
  -> 대시보드 도착
```

필수 준비 상태는 워크스페이스 읽기, 핵심 플랫폼 파일 존재, 스냅샷 생성 가능 여부다. 선택 기능은 CLI 어댑터, 알림 채널, 브라우저 자동화, 고급 검증 도구다.

## 작업 실행 흐름

사용자가 작업을 시작하면 앱은 다음 정보를 최소 입력으로 받는다.

- 목표
- 대상 프로젝트 또는 워크스페이스
- 원하는 산출물

선택 입력은 다음이다.

- 작업 깊이
- 알림 채널
- work mode
- 선호 도구

작업 중에는 터미널 로그만 보여주는 것이 아니라 timeline을 보여준다.

- 현재 단계
- 단계별 경과 시간
- 활성 에이전트와 subprocess
- 생성된 파일
- 대기 중인 사용자 결정
- 검증 결과
- 커밋/푸시 상태

## 질문과 병목 처리

AI가 사용자에게 질문해야 할 때는 전체 작업을 멈추지 않는다. 질문은 결정함에 기록하고, 의존성이 없는 작업은 계속 진행한다.

질문 항목은 다음 정보를 포함해야 한다.

- 작업 ID
- 질문
- 영향 범위
- 기본 가정
- 답변이 필요한 시점
- 답변 전 계속 가능한 작업

사용자가 나중에 답하면 저장된 컨텍스트에서 이어서 실행한다.

## 개발자/슈퍼어드민 흐름

개발자와 슈퍼어드민은 다음 기능을 볼 수 있어야 한다.

- view mode, work mode, install mode 비교
- raw registry와 설정 파일 열기
- 주요 프로젝트와 도구의 소스 코드 읽기
- validator 실행
- source provenance와 hallucination guard 결과 보기
- memory bootstrap anchor 확인
- coordination board와 decision inbox 확인
- Tauri/Electron/native packaging 비교
- signing, updater, uninstall, privacy, license release gate 확인

이 영역은 사용자 모드에서는 숨긴다. 단, 이것은 보안 경계가 아니라 복잡도 제어다.

## 실패 복구

| 상황 | 처리 |
| --- | --- |
| 워크스페이스를 읽을 수 없음 | 다른 폴더 선택, 권한 안내, 데모 모드 |
| 선택 CLI 없음 | 설정 안내, 해당 capability만 비활성화, 나머지 계속 |
| 사용자 결정 대기 | decision inbox에 기록, 독립 작업 계속 |
| 스냅샷 오래됨 | 새로고침, 마지막 생성 시간 표시, 경고와 함께 계속 |
| 업데이트 실패 | 현재 버전 유지, 재시도, 수동 다운로드 안내 |

## MVP 화면

1. 워크스페이스 선택
2. 워크스페이스 홈
3. 작업 시작
4. 실행 timeline
5. decision inbox
6. 히스토리와 산출물
7. 설정과 capability
8. 슈퍼어드민 콘솔

## 검증 기준

- 사용자는 설치형 앱 사용과 레포지토리 개발자 설정의 차이를 이해할 수 있어야 한다.
- 첫 실행에서 워크스페이스 열기, 만들기, 데모 보기 경로가 있어야 한다.
- 선택 기능 누락이 핵심 대시보드와 히스토리 사용을 막지 않아야 한다.
- 작업 실행 화면은 진행 단계, 시간, 근거, 산출물, 사용자 결정, 검증 상태를 보여야 한다.
- 사용자 모드는 간단해야 하고, 개발자/슈퍼어드민 모드는 내부 도구를 볼 수 있어야 한다.
