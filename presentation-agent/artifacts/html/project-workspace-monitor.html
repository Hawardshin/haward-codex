workspace-monitor

문서 기반 운영 상태를 웹에서 보이게 만든다

히스토리, 프로젝트, 요구사항, 스펙, 평가, 폴더 구조를 snapshot으로 모아 Next.js UI에서 탐색한다.

  • framework-slidev-official
  1. workspace-monitor는 이 저장소의 관측성 프로젝트입니다.
  2. 문서와 히스토리가 많아질수록 사람이 한눈에 볼 UI가 필요합니다.
  3. 근거 문서: workspace-monitor/README.md

Why

운영 구조는 보이지 않으면 유지되지 않는다

  • 완료 작업은 `_history`에 남지만, 폴더만 보면 전체 흐름을 빠르게 보기 어렵다.
  • 요구사항과 스펙과 평가는 서로 다른 폴더에 흩어져 있다.
  • 프로젝트가 늘수록 사람이 보는 navigation layer가 필요하다.
  • public 전환 시 Vercel 배포 가능한 형태가 필요하다.
  • templates-pitch
documentation needs observability
  1. 이 프로젝트는 운영 문서가 많아질수록 생기는 탐색 문제를 해결합니다.
  2. 문서 자체를 옮기는 것이 아니라, snapshot으로 읽어 UI에서 보여줍니다.
  3. 근거 문서: workspace-monitor/README.md, workspace-monitor/specs/

Architecture

collector가 repository를 읽고 정적 snapshot을 만든다

  • `scripts/collect-workspace.mjs`: 문서와 구조 수집
  • `src/generated/workspace-snapshot.json`: commit되는 데이터
  • `public/workspace-snapshot.json`: 브라우저 접근용 복사본
  • `components/MonitorShell.tsx`: dashboard UI
  • `next.config.mjs`: static export
  • framework-revealjs-official
1collect2snapshot3render4export5deploy
  1. 핵심은 Next.js 앱이 런타임에 저장소를 읽는 것이 아니라, build 전에 snapshot을 만든다는 점입니다.
  2. 이 방식은 Vercel static export와 잘 맞고, public 전환 전 snapshot을 검토할 수 있습니다.
  3. 근거 문서: workspace-monitor/scripts/collect-workspace.mjs, README.md

Public Boundary

Vercel 배포 전에 snapshot 공개 범위를 반드시 확인한다

  • private note와 secret이 포함되지 않았는지 확인한다.
  • raw prompt나 로컬 절대 경로가 공개 가능한지 본다.
  • 공개하면 안 되는 문서는 collector 범위를 조정한다.
  • `pnpm run collect`와 `pnpm run build`를 다시 실행한다.
  • templates-pitch
public snapshot must be reviewed
  1. workspace-monitor는 public 배포를 염두에 두지만, 이 저장소는 현재 private입니다.
  2. 따라서 public 전환 전에는 snapshot을 반드시 검토해야 합니다.
  3. 근거 문서: workspace-monitor/README.md 공개 전 점검
