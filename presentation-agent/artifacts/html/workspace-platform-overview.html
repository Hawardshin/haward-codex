Problem

AI와 오래 일할 때 진짜 문제는 기억의 손실이다

  • 좋은 답변도 출처와 맥락이 없으면 다음 작업에서 다시 의심해야 한다.
  • 프로젝트가 늘어나면 폴더, 스펙, 히스토리, 코드가 서로 어긋난다.
  • 모델의 추정과 실제 근거가 섞이면 계획 품질이 빠르게 떨어진다.
  • 대화 컨텍스트가 길어질수록 이전 결정은 점점 찾기 어려워진다.
  • theory-duarte-resources
  • research-slideaudit
lost context becomes platform debt
  1. 이 플랫폼은 AI 성능 자체보다, AI와 일할 때 생기는 운영 문제를 먼저 해결합니다.
  2. 문제는 답변 하나가 아니라 작업의 연속성입니다. 어떤 근거로 결정했고, 어떤 요청이 어떤 결과가 됐는지가 남아야 합니다.

Big Idea

플랫폼의 단위는 답변이 아니라 검증 가능한 작업 흐름이다

  • 사용자 의도는 요구사항 후보가 된다.
  • 요구사항은 스펙, 계획, 작업, 검증, 추적성으로 내려간다.
  • 결과는 평가와 재작업을 통과한 뒤 히스토리와 커밋으로 남는다.
  • theory-duarte-resources

Operating Loop

모든 의미 있는 작업은 하나의 루프로 닫힌다

  • 웹 우선 조사와 memory bootstrap으로 시작한다.
  • 작업 모드로 루프의 강도를 정한다.
  • 요구사항과 스펙으로 실행을 좁힌다.
  • 검증, grounding, 평가를 통과하고 push한다.

  • 아키텍처 이론과 실무자 의견을 분리해 기록한다.
  • 폴더 구조 후보와 폴더 의미를 남긴다.

Speed Control

모든 작업을 full loop로 돌리지 않고, 모드와 병렬 계획으로 속도를 조절한다

  • `quick`: 작은 작업
  • `standard`: 일반 구현/문서 작업
  • `ship_first`: 먼저 결과를 내고 개선을 백로그화
  • `research`: 근거 수집 중심
  • `governance`: 구조와 규칙 변경
