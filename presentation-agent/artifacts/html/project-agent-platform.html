agent-platform

에이전트가 일하는 방식을 제품화하는 중심 엔진

조사, 계획, 평가, grounding, memory, 설정 검증, 알림을 재사용 가능한 플랫폼 레이어로 묶는다.

  • theory-duarte-resources
  1. agent-platform은 이 저장소의 중심 프로젝트입니다.
  2. 루트 저장소가 작업 공간이라면, agent-platform은 에이전트의 공통 실행 기준을 만드는 엔진입니다.
  3. 근거 문서: agent-platform/README.md

Scope

여기에 들어오는 것은 공통 플랫폼 능력이다

  • agent specs와 platform-level configs
  • planning helpers와 evaluation helpers
  • memory bootstrap과 config contract
  • research profiles와 coding readiness checks
  • Slack/Discord/Teams notification integration
  • templates-pitch
shared capability, not domain experiment
  1. 도메인 실험이나 개별 앱은 agent-platform에 넣지 않습니다.
  2. 재사용 가능한 플랫폼 모델과 평가/계획/검증 능력만 이 프로젝트의 소유입니다.
  3. 근거 문서: agent-platform/README.md, _ops/projects/registry.json

Modules

소스 구조는 에이전트 운영 책임별로 나뉜다

  • `core`: domain model과 registry
  • `planning`: research, coding, parallel, spec reconciliation
  • `evaluation`: evaluator, skeptic, hallucination guard
  • `memory`: durable context bootstrap
  • `governance`와 `integrations`: config contract와 notifications
  • framework-slidev-official
1core2planning3evaluation4memory5integration
  1. 이 프로젝트는 Python-first 구조입니다.
  2. 기능이 늘어도 책임별 모듈이 분리되어 있어 에이전트를 추가하거나 평가 기준을 늘리기 쉽습니다.
  3. 근거 문서: agent-platform/src/agent_platform/

Research + Planning

조사 결과는 계획 준비 상태를 통과해야 구현으로 넘어간다

  • `research-insight-planner-agent`: answer-engine style research
  • `coding-research-agent`: stack docs, version, issue/discussion, architecture
  • `parallel-work-planner-agent`: lane, dependency, merge gate
  • `spec-reconciliation-agent`: spec/source drift classification
  • research-slideaudit
4 planning agents already modeled
  1. 이 프로젝트의 핵심은 조사 자체가 아니라 구현 가능한 계획으로 인정되는 조건입니다.
  2. 특히 코딩 조사는 공식 문서, 이슈/토론, 아키텍처, 언어 선택, 폴더 의미를 요구합니다.
  3. 근거 문서: agent-platform/docs/research-insight-planner-agent.ko.md, coding-research-agent.ko.md

Evaluation

결과물은 평가와 grounding 없이는 최종이 아니다

  • `work-evaluator-agent`: close-out gap 검사
  • `hallucination-guard-agent`: 주장별 근거와 검증
  • `knowledge-skeptic-agent`: 내부 지식 베이스 재검증
  • `skill-validator`: 만든 스킬의 trigger와 forward-test 관리
  • research-slideaudit

Settings

공유 설정은 파일만 열어도 왜 있는지 이해되어야 한다

  • memory bootstrap manifest
  • research source registries
  • work mode registry
  • notification channel settings
  • spec reconciliation template
  • framework-marp-official
self-documenting configs
  1. 사용자가 설정 파일만 봐도 무엇을 참고하는지 알 수 있어야 한다고 요청했습니다.
  2. 그래서 reader_guide, reference_links, structure_rules, field_guide를 요구하는 config contract가 있습니다.
  3. 근거 문서: agent-platform/src/agent_platform/governance/config_contract.py

Commands

CLI는 에이전트 운영을 반복 가능한 검사로 바꾼다

  • `evaluate-work`: 완료 작업 평가
  • `check-grounding`: 사실 주장 검증
  • `plan-from-research`: 조사 기반 계획 검사
  • `complete-coding-research`: 코딩 조사 readiness
  • `check-memory-bootstrap`: durable context readiness
  • framework-revealjs-official
1evaluate2ground3plan4code5memory
  1. agent-platform의 CLI는 에이전트 행동을 사람이 다시 실행할 수 있는 형태로 고정합니다.
  2. 이것이 단순 문서와 다른 점입니다. 검사가 반복 가능해야 합니다.
  3. 근거 문서: agent-platform/README.md Commands
