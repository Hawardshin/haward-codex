# Prohibition-To-Positive Constraint Spec

## Purpose

Create a shared operating structure that does not assume AI understands prohibition-heavy instructions as stable behavior rules, and instead converts them into positive behavior contracts with checkable gates.

## Scope

- Add a philosophy principle.
- Add a prohibition rewrite contract to the AI usage gap profile.
- Update persistent instructions, workflow, and reusable prompt.
- Update requirement, history, and evaluation records.

## Requirement

- `REQ-WS-078`

## Acceptance Criteria

- Prohibition-heavy instructions convert into `positive_target_behavior`, `allowed_actions`, `replacement_action`, and `verification_or_enforcement`.
- Risky areas require structural controls rather than prompt prohibition alone.
- Philosophy traceability links the new principle to execution and validation targets.
- Config contract, philosophy trace, memory bootstrap, and docs audit pass.
